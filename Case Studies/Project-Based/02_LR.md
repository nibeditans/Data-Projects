# Case Study 3: Why Different Implementations Change Understanding, Not the Truth?

## Context

The earlier case studies focused on when β-coefficients become meaningful. This final case study focuses on something subtler: **If the Mathematics of linear regression is fixed, why does the model feel different to reason about across implementations?**

To explore this, the same regression problem is examined through three lenses:

* **Manual β computation** (matrix formulation)
* **Scikit-learn** (high-level abstraction)
* **SciPy / NumPy** (procedural and numerical focus)

These notebooks are not competitors. They are perspectives.


## Same Model, Different Cognitive Load

At a Mathematical level, nothing changes:

* the objective function is the same
* the β-coefficients solve the same optimization problem
* the fitted values are equivalent up to numerical precision

Yet the experience of working with the model changes dramatically.

This difference is not about accuracy. It is about **where understanding is demanded**.


## Manual Computation: Transparency by Necessity

Manually computing β exposes the full structure of linear regression:

* design matrices
* normal equations
* matrix inversion and projections

Nothing is hidden. Every assumption is visible.

This approach is cognitively demanding but conceptually grounding. It makes explicit that β is not a magic output, it is the result of a geometric and algebraic process acting on data.

Manual computation builds intuition, even when it is impractical for real-world use.


## Scikit-learn: Abstraction for Application

Scikit-learn prioritizes usability and consistency.

With minimal code, the model can be:

* fitted
* evaluated
* deployed

This abstraction is intentional. It reduces friction and enables scale.

The trade-off is that mechanics disappear behind interfaces. β remains correct, but the path to it is obscured. Understanding must be imported from elsewhere, it is not enforced by the workflow.

This is not a flaw. It is a design choice.


## SciPy and NumPy: Numerical Explicitness

SciPy and NumPy occupy a middle ground.

They expose:

* numerical procedures
* optimization routines
* array-level operations

without fully abstracting the model away.

This makes them well-suited for exploration and experimentation. The focus shifts toward how numerical solutions are obtained, rather than why those solutions are meaningful.


## What Actually Changes?

Across all three approaches:

* the regression model is the same
* the β-coefficients encode the same relationships
* the predictions are equivalent

What changes is **how responsibility for understanding is distributed**:

* manual methods force understanding
* abstractions assume it
* numerical tools partially reveal it


## Key Takeaway

Implementation choices do not change the truth of linear regression.

They change:

* what is visible
* what is hidden
* what the practitioner must reason through

β does not become meaningful because of a library. It becomes meaningful because the analyst understands the conditions under which it is estimated.

This case study completes the project by reinforcing a central theme: **Models do not explain themselves. Understanding is earned, not returned as output.**
